One application workflow

The selected application remains the unit of work.

Use a pinned runtime in an independent repository or Arcane's live runtime in its integrated checkout.

  1. 01

    Scaffold or enroll

    Create the Arcane repository shape or add only the missing files to an existing project.

    arcane new my-app --git
  2. 02

    Develop and check

    Serve the selected app with the pinned runtime, run focused tests, and validate its declared contract.

    arcane dev
  3. 03

    Package and verify

    Produce a deterministic browser release and authenticate its complete file inventory before use.

    arcane package
  4. 04

    Distribute independently

    Push source to its private repository and publish only the artifact channel appropriate for that app.

    arcane repo push

One headless engine, every control surface

The CLI, generated CI, future Arcane Developer control panel, and Codex all consume the same operations, structured events, cancellation behavior, and exit status. The graphical control panel will not become a second build system.

Command center

A stable CLI for people, automation, and AI.

Use arcane inside an installed project. arcane-os is the equivalent collision-safe fallback.

Local development before npm publication 
# From the arcane-os-sdk checkout
npm ci
npm run check
npm run pack:local
node ./bin/arcane.mjs new local-app --path ../local-app --git

# From the generated app repository
cd ../local-app
npm install --save-dev --save-exact ../arcane-os-sdk/arcane-os-0.1.0-dev.0.tgz
npm run check

Use a packed tarball today. Local directory dependencies may become links and are intentionally rejected.

  • Checks the exact managed-service registration on supported hosts

  • Keeps Ollama optional for packaging and non-AI applications

Architecture that can grow

Trust facts are verified once and carried forward.

The SDK is arranged around explicit boundaries that a future graphical control panel and native builders can reuse.

◎

Immutable receipts

Runtime and release identities bind canonical locations, complete inventories, policy, and exact bytes.

Explicit target inputs

Distribution boundary

Keep source ownership and runtime licensing distinct.

The synchronized Arcane runtime and packager are currently AGPL-3.0-only. A separate commercial agreement is required before treating the existing commercial notice as permission to distribute a closed-source app that bundles that runtime.
