One application workflow

The selected application remains the unit of work.

Use a pinned runtime in an independent repository or Arcane's live runtime in its integrated checkout.

  1. 01

    Scaffold or enroll

    Create the Arcane repository shape or add only the missing files to an existing project.

    arcane new my-app --target portable --git
  2. 02

    Develop and check

    Serve and validate one app by default, or select the integrated shared/Core profile with --scope shared for one exact focused test or canonical check.

    arcane dev
  3. 03

    Package or build

    Package a deterministic browser release, or build exactly one declared portable, Windows, Linux, or Android development target.

    arcane package / arcane build
  4. 04

    Distribute independently

    Push source to its private repository and publish only the artifact channel appropriate for that app.

    arcane repo push

Command center

A stable CLI for people, automation, and AI.

Use arcane inside an installed project. arcane-os is the equivalent collision-safe fallback.

Local development before npm publication 
# From the arcane-os-sdk checkout
npm ci
npm run check
npm run pack:local
node ./bin/arcane.mjs new local-app --path ../local-app --git

# From the generated app repository
cd ../local-app
npm install --save-dev --save-exact ../arcane-os-sdk/arcane-os-0.1.0-dev.2.tgz
npm run check

Use a packed tarball today. Local directory dependencies may become links and are intentionally rejected.

Platform contract

Explicit targets. Honest development boundaries.

The adapter protocol supports browser plus five explicitly paired native development targets without overstating production readiness.

TargetFormatsStatusNext boundary
BrowserDirectoryAvailableVerified package and loopback run
PortableCore directoryAvailableExplicit --arcane-root; verified, not executable
Windows x64EXE bundleAvailableExplicit --arcane-root; unsigned-local-test
Linux x64DEBAvailableExplicit --arcane-root; unsigned-local-test
Linux ARM64DEBAvailableExplicit --arcane-root; compatible native ARM64 toolchain and remote evidence workflow
Android ARM64APK onlyAvailableExplicit --arcane-root; development-signed, no native ABI; physical/native ARM64 device for run

Development evidence stays development evidence. Every native target requires an explicit compatible --arcane-root and matching scaffold descriptor. Portable cannot run directly. Windows and both Linux DEBs are unsigned-local-test; Android is a development-signed, architecture-neutral APK with no native ABI. Linux ARM64 has exact-SHA native workflow evidence for AArch64 build, retained verification, sandboxed WebKit readiness, and owned cancellation. Android has exact-SHA physical ARM64/API 37 evidence for build, process-bound readiness, cancellation, uninstall, and absence. AAB, release signing, publishing, and update continuity remain deferred.

Distribution boundary

Keep source ownership and runtime licensing distinct.

The synchronized Arcane runtime and packager are currently AGPL-3.0-only. A separate commercial agreement is required before treating the existing commercial notice as permission to distribute a closed-source app that bundles that runtime.
