Explicit providers

Build one native target without pretending it is another.

Portable assembles a non-executable Core payload from the installed SDK. Windows, Linux, and Android executable targets pair with their compatible Arcane OS provider. Unsupported toolchains fail; they never fall back to another target.

1. Declare the exact target

Scaffold with the target, or add it to the canonical schema-2 app descriptor and validate it. A command-line target does not override a missing descriptor declaration.

Current SDK channel · target-aware scaffold
npx arcane-os@latest new my-app --path ./my-app --target windows-x64 --git
cd my-app
npm install

Expected: the descriptor declares both browser and windows-x64 and includes the required raster application icon. Executable native targets still require their explicit compatible --arcane-root; portable does not.

2. Diagnose the selected provider

native-doctor validates the selected provider and local prerequisites without creating a release artifact. Portable selects the installed SDK provider by default. Pass --arcane-root for the executable checkout-backed targets.

Provider checks
# Installed-SDK portable provider
npm exec -- arcane native-doctor --target portable

# Explicit checkout-backed Windows provider
npm exec -- arcane native-doctor --target windows-x64 --arcane-root "../Arcane OS"
Do not run native-prepare immediately before every build.

It is a standalone toolchain diagnostic. The build already prepares the selected toolchain state.

3. Build and run in one process

run owns the selected build and supported executable launch. The native provider retains the state required for that operation; tests and artifact verification remain explicitly selected work.

Windows x64 development run
npm exec -- arcane run --target windows-x64 --arcane-root "../Arcane OS" --output-root "../arcane-native-output"
Linux and Android variants
# Linux x64
npm exec -- arcane run --target linux-x64 --arcane-root "../Arcane OS" --format deb --signing unsigned-local-test

# Linux ARM64 on a compatible native ARM64 toolchain
npm exec -- arcane run --target linux-arm64 --arcane-root "../Arcane OS" --format deb --signing unsigned-local-test

# Android on a connected physical ARM64 device
npm exec -- arcane run --target android-arm64 --arcane-root "../Arcane OS" --format apk --signing development

4. Treat portable as a directory

The portable provider creates an app-scoped Core directory from the installed SDK. It intentionally has no executable run path, native bridge, product policy, or proof that an eventual composed host supplies the needed services.

Installed-SDK portable output
npm exec -- arcane native-doctor --target portable
npm exec -- arcane build --target portable

Applications compose explicit services through the reusable Core runtime and host lifecycle. The browser Core client owns renderer transport and correlation, while the portable packaging contract defines the payload and the obligations of a real host.

Release-readiness principle

Verify the selected output at its actual boundary. A portable directory confirms payload assembly, not an executable host. A source check, browser package, or different architecture cannot substitute for the selected executable native artifact. Production installers, platform signing, and public release publication are separate release-system concerns.

  • Descriptor target and command target match.
  • Portable uses the installed SDK provider without --arcane-root.
  • Executable target providers use an explicit compatible Arcane root.
  • Output root stays outside an integrated Arcane checkout.
  • Build and run use the selected artifact and its owning provider.
