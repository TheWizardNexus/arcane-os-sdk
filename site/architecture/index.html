Two workspace profiles, shared runtime ownership

External

A standalone app uses its repository root and reads its pinned SDK through direct node_modules/<dependency>/ browser routes. Explicit multi-app, virtual and physical layouts remain supported. Packaging preserves the selected destinations inside the complete app release.

Integrated

An Arcane OS checkout consumes its selected SDK projection or an explicit development-only live SDK source mount. The SDK owns portable runtime source. Initialization creates only app-owned files and preserves integrated root configuration.

The descriptor and release are different artifacts

A standalone app owns root arcane-app.json; an explicitly nested app uses apps/<id>/arcane-app.json. This authored schema-2 descriptor projects the schema-1 package contract. Packaging preserves the selected root or nested app layout and records the complete inventory in ARCANE_APP_RELEASE.json.

The default release directory is dist/<id>/. An app's schema-1 outputDirectory selects another workspace-relative destination directly, without an added app-ID suffix. A release bundle adds the canonical descriptor and complete selected payload. Saved source and managed import maps remain the package inputs; refresh maps through arcane import-map or ordinary arcane dev startup.

Native providers are explicit pairings

The SDK never searches for a mutable global toolchain. A native command names one target and one --arcane-root; the selected Arcane checkout supplies the fixed provider module for that process generation.

Native lifecycle
doctor → prepare → plan → build → run

Verification is a separate explicitly selected operation. Portable intentionally stops before run. Other current development providers launch only on their compatible host or device.

Keep verification tied to its selected output

Native planning and providers consume the complete selected release and its declared app dependencies. Explicit release verification checks the observed descriptor, package contract and file inventory. Its result describes that artifact and operation; browser behavior, native launch, production signing and installation require evidence from their actual boundaries.
