The SDK belongs in npm; the app belongs in its own repository.

The maintained copy lives in the SDK repository as documentation. A real app pins the SDK in devDependencies, commits its npm lockfile, and uses npm exec -- arcane or the generated npm scripts.

Step 01

Create the application repository

After the development package is published, npm can bootstrap and then install the exact SDK version declared by the scaffold.

PowerShell
npx arcane-os@dev new hello-world --path .\hello-world --target windows-x64 --git
Set-Location .\hello-world
npm install
Current development checkout

arcane-os is not yet published. Today, run npm run pack:local in the SDK checkout and install the resulting .tgz through npm. The quick-start guide shows that exact temporary path.

Step 02

Know the project shape

The app owns its source and descriptor. The npm package supplies shared runtime files during packaging; those files are not copied into app source.

hello-world/
├── apps/hello-world/
│   ├── img/icon.png
│   ├── modules/App.js
│   ├── test/app.test.mjs
│   ├── arcane-app.json
│   ├── arcane-package.json
│   ├── hello-world.css
│   ├── index.html
│   └── manifest.json
├── arcane-packager.json
├── arcane.lock.json
└── package.json

Step 03

Write the smallest visible app

The document establishes the app identity and repository-root URL base, then loads the shared Arcane theme before the app stylesheet and module.

apps/hello-world/index.html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="arcane-app-id" content="hello-world">
  <base href="../../">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Arcane Hello World</title>
  <link rel="stylesheet" href="./arcane/css/theme.css?v=1">
  <link rel="stylesheet" href="./arcane/css/primitives.css?v=1">
  <link rel="stylesheet" href="./apps/hello-world/hello-world.css?v=1">
  <script type="module" src="./arcane/modules/ThemeBootstrap.js?v=1"></script>
</head>
<body>
  <main class="app-shell">
    <h1>Hello, Arcane World!</h1>
    <p id="app-status" role="status" aria-live="polite">Ready to say hello.</p>
    <button id="app-action" class="arcane-button" type="button">Say hello</button>
  </main>
  <script type="module" src="./apps/hello-world/modules/App.js?v=1"></script>
</body>
</html>
apps/hello-world/modules/App.js
const action=document.querySelector('#app-action');
const status=document.querySelector('#app-status');

function sayHello(){
    status.textContent='Hello from Arcane OS!';
}

action?.addEventListener('click',sayHello);

Step 04

Declare what may be packaged and built

The schema-2 descriptor is the app-owned identity and policy. It declares no capabilities because this greeting performs no privileged work.

apps/hello-world/arcane-app.json · complete descriptor
{
  "schemaVersion": 2,
  "id": "hello-world",
  "displayName": "Arcane Hello World",
  "description": "Minimal Arcane OS Hello World application.",
  "version": "0.1.0",
  "publisher": {
    "id": "the-wizard-nexus",
    "name": "The Wizard Nexus"
  },
  "package": {
    "entry": "index.html",
    "strategy": "static",
    "include": ["hello-world.css", "index.html", "img/icon.png", "manifest.json", "modules"],
    "exclude": [],
    "shared": ["browser-runtime"]
  },
  "permissions": { "capabilities": [], "methods": [] },
  "security": {
    "connectOrigins": [],
    "frameOrigins": [],
    "mediaOrigins": []
  },
  "native": {
    "type": "app",
    "icon": "img/icon.png",
    "order": 100,
    "bundledApps": []
  },
  "requirements": {
    "arcaneProtocol": "arcane/1",
    "minimumCoreVersion": "0.8.12",
    "features": []
  },
  "targets": ["browser", "windows-x64"]
}

Step 05

Check it, then use the browser loop

The scripts resolve the CLI from the app's npm dependency. check validates the workspace, locked SDK runtime, descriptor projection, package policy, and focused app tests.

Application repository
npm run check
npm run dev

Result: a checked browser app at the loopback URL printed by the owned development server.

Step 06

Build the Windows development executable

The current native provider lives behind one explicit compatible Arcane OS checkout. Building authenticates the browser release, prepares the provider once, compiles one target, and verifies the resulting bundle.

Leave a verified executable bundle
npm exec -- arcane native-doctor --target windows-x64 --arcane-root "..\Arcane OS"
npm run build -- --arcane-root "..\Arcane OS"

Output: build/windows-x64/hello-world/ArcaneApp-hello-world.exe. Keep the complete containing directory.

Or build, verify, and launch in one operation
npm run run -- --arcane-root "..\Arcane OS"
Choose build or run.

run already performs build → verify → launch in one receipt-owning process. Do not run it immediately after the separate build against the same default output. The Windows result is unsigned local-development output, not a production release.
